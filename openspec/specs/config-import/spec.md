# config-import

## Purpose

Зафиксировать существующий формат импорта конфигурации и её загрузку из браузерного хранилища. Основание: `src/app/config-file.ts`, `src/app/storage.ts` и соседние тесты. Спецификация описывает текущее поведение без новых ограничений формата.

## Requirements

### Requirement: JSON и версия формата

`parseConfigFile` SHALL принимать текст JSON с объектом в корне и целочисленным числовым полем `version`. Текущая поддерживаемая версия SHALL равняться `1`. Версии больше `1` SHALL отклоняться; целые версии меньше или равные `1` SHALL проходить дальнейшую проверку по той же схеме без миграции.

#### Scenario: Неверный JSON или корень

- **WHEN** передан неразбираемый JSON
- **THEN** результат равен `{ ok: false, errors: ["Файл не разбирается как JSON"] }`
- **AND** для корректного JSON с корнем-массивом, `null` или примитивом ошибка равна `Файл должен содержать объект конфигурации`

#### Scenario: Неподдерживаемая версия

- **WHEN** поле `version` отсутствует, не является числом или не является целым
- **THEN** возвращается ошибка `Нет поля version с целым числом`
- **AND** при `version: 2` возвращается ошибка `Версия формата 2 новее поддерживаемой 1`

#### Scenario: Более ранняя версия

- **GIVEN** конфигурация соответствует текущей схеме
- **WHEN** её версия равна `0` или `-1`
- **THEN** конфигурация принимается

### Requirement: Структура конфигурации

Конфигурация SHALL содержать массивы `users`, `groups`, `services`, `permissions`; пустые массивы допустимы. Каждая запись SHALL быть объектом. Пользователи, группы и сервисы SHALL иметь непустые строковые `id` и `name`. Пользователь SHALL иметь массив `groupIds` из непустых строк. Разрешение SHALL иметь непустые строковые `id`, `serviceId` и объект `subject` с `type`, равным `user` или `group`, и непустым строковым `id`.

#### Scenario: Пустая конфигурация

- **WHEN** передан объект с `version: 1` и четырьмя пустыми массивами
- **THEN** возвращается `{ ok: true, config: { users: [], groups: [], services: [], permissions: [] } }`

#### Scenario: Нарушение структуры

- **WHEN** отсутствует обязательный массив, запись не является объектом или обязательное поле имеет неверный тип
- **THEN** файл отклоняется со списком ошибок, указывающих поле и, для ошибок записи, позицию вида `users[1]`

### Requirement: Строковые значения

Проверка непустой строки SHALL отклонять только пустую строку, не обрезая пробелы.

#### Scenario: Строка из пробелов

- **WHEN** обязательное строковое поле содержит только пробелы
- **THEN** оно проходит проверку непустой строки

### Requirement: Уникальность и ссылочная целостность

Идентификаторы SHALL быть уникальны внутри каждого из четырёх массивов; совпадение идентификаторов между разными массивами допустимо. Каждый `groupIds` SHALL ссылаться на существующую группу. Каждое разрешение SHALL ссылаться на существующий сервис и существующего пользователя или группу согласно `subject.type`. Повторы в `groupIds` и несколько разрешений с разными `id` для одного субъекта и сервиса SHALL допускаться.

#### Scenario: Повтор идентификатора

- **WHEN** две записи массива `services` имеют одинаковый `id`
- **THEN** файл отклоняется с ошибкой для позиции повторной записи

#### Scenario: Отсутствующая ссылка

- **WHEN** членство ссылается на отсутствующую группу либо разрешение ссылается на отсутствующего субъекта или сервис
- **THEN** файл отклоняется с ошибкой, указывающей позицию записи и отсутствующий идентификатор

### Requirement: Результат проверки и отсутствие побочных эффектов

Парсер SHALL возвращать либо `{ ok: true, config }`, либо `{ ok: false, errors: string[] }`, без частичной конфигурации при ошибке. Парсер SHALL выполнять проверку без изменения текущей конфигурации и хранилища. Ошибки JSON, корня и версии SHALL завершать проверку сразу. Ошибки структуры и дубликатов SHALL накапливаться при обходе массивов; проверка ссылок SHALL выполняться только после успешной структурной проверки и накапливать найденные ошибки ссылок.

#### Scenario: Несколько ошибок ссылок

- **GIVEN** структура файла корректна
- **WHEN** одно разрешение ссылается на отсутствующий сервис, а другое — на отсутствующую группу
- **THEN** возвращаются обе ошибки и `ok: false`

### Requirement: Совместимость и экспорт

Неизвестные поля на любом уровне SHALL игнорироваться и не попадать в результат разбора. `exportConfig` SHALL сериализовать конфигурацию в JSON с `version: 1` и отступом в два пробела. Экспорт, импорт и хранение SHALL использовать один формат.

#### Scenario: Обратимость экспорта

- **GIVEN** корректная конфигурация
- **WHEN** результат `exportConfig` передан в `parseConfigFile`
- **THEN** возвращается конфигурация, равная исходной

#### Scenario: Дополнительные поля

- **WHEN** корректный файл содержит дополнительные поля в корне и записях
- **THEN** файл принимается, а дополнительные поля отсутствуют в возвращённой конфигурации

### Requirement: Загрузка из браузерного хранилища

`loadConfig` SHALL читать ключ `access-policy-simulator:config` переданного `Storage` и проверять сохранённый текст через `parseConfigFile`. При отсутствии значения, любой ошибке разбора или исключении чтения SHALL возвращаться `seedConfig`. Загрузка SHALL не записывать и не удалять значения хранилища.

#### Scenario: Корректное сохранённое значение

- **WHEN** под ключом приложения сохранён корректный файл конфигурации
- **THEN** загрузка возвращает разобранную конфигурацию

#### Scenario: Невозможность восстановления

- **WHEN** значение отсутствует, повреждено, нарушает ссылочную целостность, имеет неподдерживаемую версию или чтение выбрасывает исключение
- **THEN** загрузка возвращает учебную конфигурацию `seedConfig`
- **AND** сохранённое значение не изменяется

### Requirement: Сохранение конфигурации

`saveConfig` SHALL записывать результат `exportConfig(config)` под ключом `access-policy-simulator:config`. Исключения сериализации или записи SHALL подавляться без передачи ошибки вызывающему коду. Дополнительная проверка конфигурации перед сохранением SHALL не выполняться.

#### Scenario: Успешное сохранение

- **WHEN** конфигурация сохраняется в доступное хранилище
- **THEN** значение под ключом приложения равно результату её экспорта

#### Scenario: Недоступное хранилище

- **WHEN** запись выбрасывает исключение, например из-за переполнения хранилища
- **THEN** `saveConfig` завершается без выбрасывания исключения
