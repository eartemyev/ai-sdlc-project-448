# Proposal

## Why

Администратору неудобно искать сотрудника подрядной команды среди всех сотрудников при последовательной проверке доступа. Перед приходом студии «Северная» нужен выбор группы, который сократит список до её участников.

## What Changes

- Добавить перед полем «Сотрудник» фильтр «Группа» с исходным значением «Все группы».
- Показывать участников выбранной группы по `User.groupIds`, сохраняя возможность проверить каждого отдельно.
- Сохранять выбранного сотрудника, если он проходит фильтр; иначе сбрасывать его и результат проверки, сохраняя выбранный сервис.
- Обработать пустые группы и замену конфигурации импортом без скрытого выбора сотрудника.
- Фильтр действует только на выбор сотрудника для проверки доступа. Создание сотрудников и групп, изменение членства, массовая проверка и фильтрация редактора разрешений вне объёма изменения. «Северная» и восемь участников — пример данных, а не встроенная группа.

## Capabilities

### New Capabilities

- `employee-selection`: выбор сотрудника для проверки доступа с фильтрацией по группе и согласованным состоянием выбора.

### Modified Capabilities

Нет. Правила `access-calculation` и `config-import` сохраняются.

## Impact

- `src/components/App.tsx`: фильтр, производный список сотрудников и согласование выбора с текущей конфигурацией.
- `src/components/App.test.tsx`: сценарии фильтра, результата проверки и импорта через существующий интерфейс.
- Используются текущие `config` и `checkAccess` из `useSimulator`; новые зависимости и изменение формата конфигурации не требуются.
- Выбор фильтра остаётся состоянием экрана: конфигурация и браузерное хранилище при фильтрации не меняются, сетевые запросы не добавляются.
