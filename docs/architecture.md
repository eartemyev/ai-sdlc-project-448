# Архитектурные правила

Приложение разложено на три каталога, и три правила держат эту раскладку. Независимое ревью сверяет дифф с этим документом, а автоматические проверки архитектуры привязаны к тем же каталогам.

## Каталоги

| Каталог | Что в нём лежит |
| --- | --- |
| `src/domain` | Модель данных (`model.ts`) и расчёт доступа (`access.ts`). Чистые функции без обращений к браузеру и без чтения часов. |
| `src/app` | Слой приложения. Хранилище браузера, формат файла конфигурации, операции над разрешениями и хук `useSimulator`, который отдаёт компонентам всё нужное. |
| `src/components` | Экраны на React и Mantine. Показывают данные и передают действия человека в слой приложения. |

## Правила

### Единый модуль расчёта для всех экранов

Доступ сотрудника к сервису считает один модуль, `src/domain/access.ts`. Каждый экран берёт результат из него и не пересчитывает доступ по-своему, иначе два экрана рано или поздно ответят по-разному. Новая логика доступа, например срок действия разрешения или объяснение источников, добавляется в этот модуль.

### Момент расчёта передаётся в расчёт явно

Модуль расчёта не читает часы. В нём нет `Date.now()` и `new Date()` без аргументов, момент приходит параметром `at`. Слой приложения берёт текущее время и передаёт его вниз, а тест подставляет любой момент и получает повторяемый результат.

### Компоненты обращаются к конфигурации только через слой приложения

Компонент не читает `localStorage` и не импортирует модуль хранилища. Он получает конфигурацию и операции из `useSimulator` и результат расчёта из `checkAccess`. Компонент также не импортирует `src/domain`, расчёт ему отдаёт слой приложения.

## Где живут общие типы

Типы данных (`Config`, `User`, `Group`, `Service`, `Permission`, `Subject`) и типы результата расчёта (`AccessResult`, `AccessSource`) объявлены в `src/domain`, потому что их смысл задаёт расчёт и модель. Слой приложения реэкспортирует их из `src/app/index.ts`. Компоненты импортируют из `../app` всё, включая типы, и исключения для `import type` из `src/domain` нет. Граница одна для значений и для типов, поэтому правило про импорты не приходится читать с оговорками.

Новый общий тип объявляется в `src/domain`, а если он нужен компонентам, реэкспортируется из `src/app/index.ts`. Типы, которые нужны только слою приложения, например `GrantResult` и `ImportResult`, объявляются прямо в `src/app/index.ts`.

## Тесты

Тесты лежат рядом с кодом и называются `*.test.ts` и `*.test.tsx`. Правила импортов описывают код приложения. Тесты компонентов вправе брать из `src/app` учебные данные, ключ хранилища и функции формата файла, чтобы подготовить состояние браузера и сверить его после действия.

## Проверки

`make lint-arch` запускает ast-grep по `src` с правилами из каталога `rules`. В стартере каталог пуст, поэтому цель проходит. Свои правила студент добавляет туда файлами `rules/*.yml`.
